Two immutable presets ship as `graphraumThemes.dark` and `graphraumThemes.light`. `graphraumTheme` remains the dark alias.

```ts
import { graphraumTheme, graphraumThemes } from "@domudev/graphraum";

console.log(graphraumTheme.background); // "#040f0f"
console.log(graphraumThemes.light.background); // "#fcfffc"
```

Selection is a color change inside the existing instanced node mesh. It deliberately does not add a halo mesh or another rendering pass, so the two-draw-call baseline remains true.

## Override without forking

Pass a named preset, or override only the tokens your product owns. Switch at runtime with `setTheme` / `setBackground`.

```ts
const graph = new Graphraum(container, {
  theme: "light", // or { node: "#6d5bd0", selectedNode: "#fcfffc" }
});

graph.setTheme("dark");
graph.setBackground("transparent"); // host CSS color / gradient / pattern shows through
graph.setBackground({
  type: "pattern",
  source: patternCanvas, // HTMLCanvasElement | HTMLImageElement | ImageBitmap | …
  repeat: [4, 4],
});
```

Use `"transparent"` / `null` when the product owns atmosphere (CSS grid, noise, brand gradient) behind the WebGL canvas. Use a pattern background (`type: "pattern"` with a `source`) when the pattern must live inside the WebGL scene.

Per-node colors remain available for semantic categories:

```ts
graph.setData({
  nodes: [
    { id: "person:ada", position: { x: -20, y: 0 } },
    { id: "place:london", position: { x: 20, y: 0 }, color: "#73c7a5" },
  ],
  edges: [{ id: "born-in", source: "person:ada", target: "place:london" }],
});
```

## Keep meaning outside color alone

The WebGL surface is not the accessibility tree. Applications should mirror focus and selection into an accessible node list, expose labels in HTML, and pair semantic colors with text, shape, or filtering controls. graphraum owns the fast visual primitive; the host owns understandable interaction.

## Built-in node shapes

Arbitrary HTML per node is not the dense rendering path: it would trade away batching, viewport materialization, and the 100k-node target. The [`defineVisuals()` translation layer](../node-edge-presentation/) maps typed domain attributes to node and edge visuals once at ingestion, then compiles them into GPU buffers. Titles, properties, and host-owned action descriptors remain available by entity ID.

`circle`, `square`, `diamond`, `hexagon`, `triangle`, `pill`, and `rounded` are rendered as signed-distance fields on one instanced billboard geometry. Mixing them does not add meshes, materials, or draw calls, and the same shapes face the camera in 2D and 3D. Picking applies the same shape boundary—including any stroke—in world space for 2D and projected screen space for 3D.

Every shape accepts an independent `width` and `height` (square by default) plus an optional `strokeWidth` and `strokeColor` for an SDF ring around the outer edge. `strokeColor` falls back to `theme.nodeStroke`, the third canonical Porcelain swatch, so a stroked node stays on-palette without an explicit color.

Edge width, dash styles, direction markers, and path kinds (`straight`, `quadratic`, `cubic`) render as one instanced GPU edge batch, packing segment and marker instances into the same edge draw call rather than one object per edge. Curves compile to polylines at pack time. The overview LOD tier drops markers and forces solid, theme-width, straight segments first to keep frame time flat at scale; detail renders the full per-edge style and path. A bounded overlay can project host HTML onto focused nodes; that is not the dense rendering path. See [ADR: Fidelity on demand](https://github.com/domudev/graphraum/blob/main/docs/adrs/adr-fidelity-on-demand.md).

Follow the design and benchmark acceptance criteria in [the node and edge visual translation issue](https://github.com/domudev/graphraum/issues/30).
